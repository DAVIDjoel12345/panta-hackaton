## State ownership

- API-provided: authorized content, empty collections, validation issues, freshness, membership/restriction status, approval, quote expiry, transaction observations, claim eligibility, notification status and domain errors.
- Client-derived: request loading/pending display and optimistic UI; reconcile with definitive server responses later. Backend errors must restore optimistic state rather than fabricate success.
- Frontend-only: open/closed modals, dirty or untouched forms, local image preview preparation, local draft-before-upload, viewport/responsive layout, reduced-motion animation, splash, native share cancellation, clipboard fallback, browser-offline detection.
- Development-only: /dev/ui-states, auth/community actor/scenario controls and deterministic fixtures. They are never backend identity or authorization evidence.

The additional 117 authentication and 48 community preview definitions live in src/features/auth and src/features/community/communityStates.js; see frontend docs/auth-flows/states.md and docs/community-implementation.md. Map their application errors to common/errors/domain-error.ts and their UI-only state to React. No production scenario/role-switch endpoint is proposed.

Static discovery routes (including /markets/new) list existing markets; only /create and its draft routes map to market creation. Public global moderation screens are a future platform-admin policy distinct from community moderator scope; no global ban or settlement override is proposed.
