# Live Panta and external AI integration

## Local setup

Use Node 24 or newer. Install at the root and in `backend`, copy `backend/.env.example` to ignored `backend/.env`, and put `PANTA_API_KEY` plus one external AI key there: `GEMINI_API_KEY` for Google AI Studio or `OPENROUTER_API_KEY` for OpenRouter. The backend also recognizes an existing OpenRouter key saved under `GEMINI_API_KEY` and routes it correctly. Its default OpenRouter model is `google/gemini-2.5-flash-lite`; set `OPENROUTER_MODEL` to another supported model if needed. Never put keys in a `VITE_` variable. Run `npm run build --prefix backend` then `npm run dev:full` from the root. The launcher starts backend workers on 3001/3002 in sequence, the local read gateway on 3000, and Vite on 5173. Open `http://127.0.0.1:5173`. The frontend sends `/api/v1` through the Vite proxy. `GET /api/v1/runtime/health` reports configured/missing providers without exposing keys.

Markets, categories, trades and wallet positions come from Panta through one validated server adapter. The gateway shares a 10-second catalog cache across both backend workers. Single-market detail has a 2-second shared cache. After expiry, it returns the last timestamped quote immediately while one Panta refresh runs in the background. The first uncached read still waits for Panta; the trade tape has a 5-second cache. If a refresh fails, the last timestamped snapshot may be shown for up to one minute. Account and mutation routes are never cached. The open market and chart check every 2 seconds while visible, activity every 5 seconds, and catalog every 10 seconds and visible cards every 5 seconds. Actual update latency also depends on Panta response time and when its underlying market data changes. Discovery card details load only while cards are near the viewport. Explore defaults to the complete Panta USDC API catalog, with active markets first; the lifecycle filter can narrow the list. The app automatically follows every provider cursor, requesting up to 50 rows per page, then refreshes the complete catalog while the page is visible. Visible cards separately fetch current detail quotes. Panta can return a null spot price when its RPC is unavailable; the backend saves valid observations in SQLite and displays the last valid quote with its original timestamp rather than replacing it with null. The market chart draws separate purple YES and blue NO lines from actual spot observations, while the selected side controls the highlighted value and trading ticket. It does not claim to be an exchange trade feed or show invented history; data accumulates as the app observes Panta. A provider market catalog is not a streaming price service. Community posts, accounts and transaction intent records persist in SQLite; community events use the local SSE channel. Market-linked discussions validate the market ID against Panta. AI conversations call the configured Gemini or OpenRouter API, include a retrieved Panta market snapshot when opened from a market, and disclose the active provider. A working market and AI browser check is `node scripts/panta-ai-browser-check.mjs` while the stack and debugging Chrome are running.

The catalog keeps any price supplied by Panta; a saved local observation is used only when the catalog price is absent and is labeled with its original time. Visible cards request the single-market Panta endpoint for the fuller question and current provider quote. Market detail shows Panta's exact resolution rule, source URLs, quote provenance, market type, status, trade count, and both catalog and total volume where supplied. Fields missing from Panta remain unavailable rather than being generated by the frontend.

Explore shows all API markets by default, placing active markets before resolved and cancelled markets. Panta currently returns some empty catalog titles; visible cards use the single-market title or question when available, otherwise show the market ID. Resolved cards show final outcomes without a live chart. Because the provider's `status=resolved` catalog request currently returns no rows even though its unfiltered catalog includes resolved markets, the Resolved view filters unfiltered provider pages locally.

The market detail panel includes an expandable snapshot of every market field returned through the Panta integration, alongside the retrieval time and any older metadata confirmation time. The documented API currently has no batch quote or WebSocket market feed: catalog pages refresh while Explore is visible, and only on-screen cards plus the open market make individual spot-detail requests. This avoids exceeding Panta's default read budget of 120 requests per minute while preserving accurate timestamps for any delayed quote.

Panta may temporarily return a catalog-only market response when on-chain detail is unavailable. The backend keeps the last complete provider-supplied question, resolution rule, and sources in SQLite and labels the original confirmation time when showing them beside a newer partial response. Dynamic status and prices still use the newest provider response or the separately timestamped last valid quote. Market-linked AI receives the same full question, rule, sources, and freshness markers.

## Wallet and transaction boundary

Application sign-in and Solana wallet connection are separate. The UI uses Wallet Standard. Each purchase, creation, claim or fee withdrawal has its own quote/review/sign step. `backend/src/panta/service.ts` persists an idempotent intent before and after approval; `backend/src/panta/chain.ts` decodes and validates the provider-built transaction against the verified deployment policy, wallet, market, amount, side, quote, minimum shares, network and balances, then simulates it. The app accepts a wallet-signed message only if the message is unchanged and the signer is the connected wallet. It persists the signature before broadcast and reconciles chain and Panta statuses separately. On uncertain broadcast it keeps the intent pending and blocks a new action of the same kind for that wallet. No automatic mutation retry or rebroadcast occurs. Quote/build failures require a fresh review.

The optional `PANTA_DEPLOYMENT_FILE` must be an operator-verified JSON policy containing the official genesis hash, program ID, USDC mint, share decimals, IDL file and exact instruction/account/argument rules; `SOLANA_RPC_URL` must resolve to that genesis. Without both, signing and broadcast are intentionally unavailable. Do not infer a network from the API key prefix or the sample playground. A real wallet with authorized funds and small user-approved amounts is still needed for funded E2E proof. No funded transaction was attempted in this implementation.

Each active market card offers keyboard-accessible market and AI links. Its one-hour YES/NO sparkline reads the same saved Panta spot observations as the detail chart; it appears after genuine observations and uses a waiting state otherwise. Cards show Panta's catalog image when supplied. The card's own detail read and the history read start only when the card approaches the viewport. The detail chart draws both outcomes on a fixed 0–100% scale. The market AI button carries its market ID to a prefilled contextual discussion.

Market cards now expose two separate accessible links: the card body opens the market overview, while **Get analysis with AI** automatically starts a new Signal AI conversation with that market ID, its latest Panta context, and the available dated topic coverage. The AI prompt updates when the selected market changes.

Live card and detail charts reject null/invalid quotes and connect actual observations at their real timestamps with solid straight segments. Purple and blue distinguish YES and NO; the selected side's change indicator uses green/red for direction. A live/delayed badge updates quote age each second. The 1h/6h/24h detail ranges use spike-preserving downsampling; the card sparkline samples the whole last hour rather than only the latest fixed number of records. Touch and mouse movement select the nearest actual quote. Resolved payout values are kept out of active spot history and labeled as settled outcomes. The documented partner API exposes USDC catalog markets and spot detail prices, but no historical chart endpoint; Panta's public website also includes older SOL markets outside this catalog, so its entire market set and historical lines cannot be reproduced through this API.

`PANTA_OPERATOR_USER_IDS` is a comma-separated list of explicit Signal user IDs for provider account reads; community ownership grants no provider administration. The separate `backend/scripts/panta-operator.mjs` CLI handles provider account login/refresh/key lifecycle with local ignored credentials. Provider keys are never returned to ordinary browser routes.

## Validation and limitations

Run `npm test --prefix backend`, `npm run build`, `npm run lint`, and `node scripts/verify-frontend.mjs`. The browser checks are `node scripts/panta-ui-check.mjs` (wallet state and mobile routes) and `node scripts/panta-ai-browser-check.mjs` (account, market and external AI). The latter requires Chrome remote debugging on port 9223 and the full stack. Provider quote/build endpoints and funded chain submissions could not be exercised without a verified deployment and wallet funds. The external API can throttle or lag; the UI reports the last received timestamp rather than implying a guaranteed stream.

Backend dependency audit currently reports transitive advisories in the Solana/Anchor dependency tree. Review and update these dependencies before production deployment. The existing local app remains a development system, not an audited trading service.

# Topic coverage in Signal AI

Opening **Discuss with Signal AI** from a market now shows dated recent (last 7 days) and earlier (days 8–90) headlines from Google News RSS. The backend searches using distinctive words from the Panta market title, caches results for 10 minutes per market and backend worker, and links each headline to its source. It sends only headline metadata and the current Panta snapshot to the configured external AI provider. The assistant is instructed to offer neutral evidence-checking suggestions, cite available dates and links, and avoid trading advice. Headline matches are search results, not verified article contents or proof of a market outcome. If the news lookup fails, the UI reports the gap and AI can still answer from the Panta snapshot.

Explore renders the first catalog page while remaining cursors load and labels that count as incomplete. Complete catalogs are kept in a bounded, 60-second in-memory cache for return visits, retaining original timestamps and marked as cached until revalidated. Background refresh preserves the previous complete catalog until every page succeeds. No account data or API credentials are stored in this cache.

Successful transaction broadcasts and confirmed reconciliation responses now notify mounted live queries to refresh positions, wallet balances/trades, intent records, creator data and markets immediately. An update arriving during a read queues a follow-up read. Failed or pending reconciliations do not trigger refresh storms. Provider Retry-After delays are honored, including delays longer than one minute. This is event-triggered refetch plus REST polling, not a Panta WebSocket stream. Wallet approvals, trade execution and claims are not automated or exercised by the read-only browser checks.
